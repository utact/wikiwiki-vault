# 로드맵

단계마다 완료 조건을 모두 충족해야 다음 단계로 넘어간다.

## 1. 가정 확인

- 작업
  - 고용보험법, 시행령, 시행규칙, 고용산재보험료징수법의 시행일 버전 목록 확보
  - 별표와 별지 서식의 추출 방법 확인(JSON 본문, HWP, PDF)
  - 고용24 저작권정책 확인
  - 행정규칙(고시) 조회 방법 확인
  - 기계가 읽는 schema 원본 형식 선정
- 완료 조건
  - 확인 결과에 따라 2단계 작업 목록 확정

## 2. 설계 확정

- 작업
  - 역량 질문 15개와 기대 답, 근거 위치 작성
  - 법령 버전 모델: 버전과 무관한 조문, 시행일 버전 기록, 경과조치, 기준 시점
  - 식별자와 앵커: 조문, 장, 절, 별표, 부칙의 `identifier`와 항·호·목·단서의 block ID
  - 수치, 표, 산정 규칙의 표현
  - 역할, 절차, 기한, 위임의 표현
  - 상태 값의 ConceptScheme과 base IRI
  - LinkML schema 원본에서 문서, SHACL, RDF 변환 생성
  - 출처 우선순위와 불일치 표기 규칙
  - 원문 경로 `<시행일자>-<MST>`와 조문·항 단위 hash
  - 인증값 치환과 커밋 전 검사
  - 이용 조건 확인 전 고용24 본문 커밋 금지
- 완료 조건
  - 역량 질문과 기대 답의 사용자 승인
  - schema와 운영 규칙의 검토 agent 재검토와 사용자 승인

## 3. 수집 pipeline

- 작업
  - 법제처 `eflaw`로 현행과 시행예정 버전 전부 수집
  - 경과조치 조회 기간의 이전 버전을 수집하고, 인용하지 않는 버전은 로컬 캐시에 보관
  - 부칙의 경과조치·적용례·특례·유효기간 조문과 그 대상 단위 목록 작성
  - 행정규칙(고시)의 현행·시행예정·조회 기간 버전 수집, 같은 행정규칙ID에 함께 실린 최저임금안 고시 제외
  - 고용24 안내의 본문 영역과 수정일 수집, 인용을 담은 원문 노트 기록
  - 커밋 전 비밀값 검사(Git pre-commit hook)
  - 별표와 별지 서식 추출
- 완료 조건
  - 응답 시행일자와 요청 시행일자 일치
  - 현행 여부를 상태 표시가 아닌 시행일자와 기준 시점으로 판정
  - 연속한 버전 사이에 바뀐 조문, 별표, 서식, 부칙, 장·절 제목마다 그 버전 공포일의 개정 표시, 법제처 조문변경여부 표시, 또는 그 버전의 새 부칙 존재
  - 사라진 단위마다 조문 이동이나 앞선 삭제 존재
  - 이미지 안 표의 텍스트가 그 텍스트를 담은 마지막 버전과 다른데 이미지 밖 본문이 같으면 실패
  - 이미지 안 표에서 복원한 줄이 테두리로 시작하고 끝나지 않으면 실패
  - 버전마다 마지막 제정·전부개정 이후 시행일이 그 버전 이하인 공포의 부칙이 모두 포함
  - 목록 페이지의 행 수와 목록 전체 건수 일치
  - 법령과 행정규칙 모두 경과조치 조회 기간의 버전 전부 수집
  - 행정규칙 응답의 시행일자가 원문 노트와 같고 본문 텍스트가 비어 있지 않음
  - 별표와 별지 서식 본문이 비어 있으면 실패
  - 고용24 안내의 본문 영역을 찾지 못하거나 모든 영역이 비면 실패
  - 고용24 안내의 빈 영역을 검토 목록에 기록
  - 다시 실행해도 새 파일 없음
  - 검사마다 결함을 심은 시험에서 실패 확인

## 4. 생성·검증 pipeline

- 작업
  - 법령 노트, 별표, 인용 관계(`cites`)를 원문에서 스크립트로 생성
  - block 날짜 산정에 필요한 이전 버전을 경과조치 조회 기간 밖까지 캐시에 수집
  - 원문 노트의 `publisher`가 가리키는 기관 노트(법제처, 한국고용정보원) 작성
  - 단위 본문이 바뀔 때만 버전을 만들고, block 버전 노드와 버전 무관 block 노드 생성
  - 조문이동이전·이후와 조문참고자료로 옮겨진 조문과 다시 쓰인 번호(고용산재보험료징수법 시행령 제56조의10)를 검토 목록으로 출력
  - 버전 날짜 검사에서 개정 표시와 날짜가 맞는 공포가 없는 단위(시행규칙 제87조, 고용산재보험료징수법 시행령 제19조의4)와 개정 표시 없이 바뀐 단위(법 제106조)를 검토 목록으로 출력
  - 개정 표시만 바뀌고 본문은 같은 단위 변경(1,537건 중 32건)의 버전 처리
  - 텍스트 없는 이미지(고용산재보험료징수법 시행령 제18조의2 계산식)는 저장한 이미지 파일을 법령 노트에 싣고, 서식에서 "?"로 바뀐 글자와 함께 검토 목록으로 출력
  - 박스 문자 없이 공백으로만 나란히 놓인 서식 글을 검토 목록으로 출력하고, 필요하면 PDF에서 인용(고용산재보험료징수법 시행규칙 별지 제22호의4서식)
  - 2020·2021년 적용 최저임금 고시의 금액은 저장한 이미지와 HWP 첨부파일에만 있어, 인용할 때 HWP 본문 추출
  - fixture 법령 노트를 실제 본문으로 교체
  - frontmatter를 RDF로 변환하고 SHACL로 검사
  - CPSV-AP 3.2.0·CCCEV 2.1.0 공식 SHACL shape 검사, PublicService의 `dct:title`·`dct:description` 출력, 상태 값과 하위 단위 종류의 ConceptScheme 선언
  - lint
  - 인용 문자열과 숫자를 원문과 대조하고, 계산식을 평가
    - 숫자는 칸 경계를 남기고, 표 칸과 별표·서식·PDF 텍스트의 줄바꿈은 이어 붙인 텍스트에서 token 단위로 대조
  - 선언되지 않은 block·인용 링크, FEEL 구문과 자료형, 결정표 일관성 검사
  - 검증 원장(`ontology/verification.jsonl`)
    - 생성 스크립트의 commit을 함께 기록해, 읽기 규칙이 바뀐 것과 원문이 바뀐 것을 구분
  - vault 노트용 markdownlint 설정
  - `reviewed` 보호 hook은 사용자 승인 후 설치
- 완료 조건
  - 결함을 심은 시험 노트에서 결함 100% 검출, 오탐 0건

## 5. 시범 구간

- 작업
  - 유형마다 한 사례를 원문부터 시각화까지 완성
    - 구직급여 수급 요건(제40조)
    - 기초일액 상·하한의 위임(제45조, 시행령, 최저임금 고시)
    - 소정급여일수 별표
    - 수급자격 제한과 정당한 이직 사유
    - 피보험자격 상실신고와 이직확인서 의무
    - 시행일 전환(고용보험법 제45조의 2028-01-01 개정)과 경과조치(고용보험법 부칙 제21473호 제3조, 고용보험법 시행령 부칙 제35934호 제4조)
- 완료 조건
  - 해당 역량 질문의 검사 통과
  - 검증 통과와 사용자 승인
  - schema 확정

## 6. 첫 분야 확장

- 작업

  - 노트가 있는 조문이 옮겨지면 identifier를 잇고, 다시 쓰인 번호의 이전 버전은 다른 노트로 생성
- 완료 조건
  - 역량 질문 전부 통과
  - lint 오류 0건
